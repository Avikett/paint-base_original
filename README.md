🗺️ Карта взаємодії (що і де відбувається)

«Світ розробника» в проєкті ділиться на три зони:
1. Власна гілка ( у Code Sandbox) – місце, де можна все ламати (не обов'язково), експериментувати, малювати, загалом «царювати».
2. Спільний проєкт (у гілці GitHub main) – «святиня», куди потрапляє тільки перевірений код, ніяких «царювань», тут – шанобливо та ввічливо.
3. Місток (Pull Request) – процес передачі коду з Code Sandbox на GitHub для перевірки та схвалення (можливо).

📝 Для ясності: «алгоритм 4П»

Щоб не плутатися, працюйте максимально механічно:

П – прийміть оновлення (початок спринту)
1. Де: вкладка GitHub у CodeSandbox, верхня панель CodeSandbox (ліворуч угорі).
2. Дія: якщо є напис «X commits behind main», треба натиснути на нього.
3. Навіщо: щоб у власну копію проєкту «прилетіли» всі оновлення, які схвалені у загальному проєкті.

П — працюйте у CodeSandbox (основна частина)
1. Де: файли власної гілки (script.js / style.css / index.html / ...).
2. Дія: пишіть код, дивіться у Preview.
3. Важливо: не виходьте зі своєї гілки (перевіряйте назву гілки знизу ліворуч або зверху посередині, там ні в якому разі не має бути «main», тільки власна гілка з нікнеймом або автоматично створеною назвою).

П — перевірте (завершення)
1. Де: вкладка GitHub (іконка котика зліва) у CodeSandbox.
2. Дія: натисніть Sync (якщо є) або знову перевірте напис «... behind main» вгорі ліворуч.
3. Навіщо: це «щеплення» від конфліктів; якщо за час вашої роботи в проєкті з'явилося щось нове, потрібно поєднати це зі своїм кодом прямо зараз (краще виправити помилку в себе, ніж відправляти «нагору» зламаний код).

П — подайте (фінал, КРИТИЧНИЙ ЕТАП); крок складається з двох частин:
1. у CodeSandbox: натисніть Commit (до вікна зверху напишіть сутність додавання, наприклад «Крок 18») та обов'язково Push (відправити на сервер).
2. на сайті GitHub: відкрийте сторінку репозиторію в браузері; якщо є жовта плашка «Compare & pull request» — натисніть її.

Результат: лише після натискання зеленої кнопки «Create pull request» на сайті GitHub, керівник проєкту отримає сповіщення і зможе прийняти відправлену роботу.
